**操作**：ホームを表示。タイトル「形式はOK。でも、そこじゃない。」を見せる。

## 1. Jevは何を返すAIか（0:35〜1:25）

**画面テロップ**：文章ではなく、選択肢と確率を返す

**読み上げ**：

「Jevは、人に読ませる返事より、アプリがそのまま使える判断を返すためのAIです。アプリ側が用意した選択肢、たとえば『名前と会社名は自然か、逆か、判断できないか』に対して、どれを選ぶかと、その選択肢の確率を返します。さらに質問によっては confidence も返ります。ただし、これは正解率の保証ではありません。普通のLLMもJSONを返せるので、JSONだけがJevの独自性ではありません。大事なのは、アプリが欲しい小さな判断を、選択肢として繰り返し扱える点です。」

**操作**：この章では概念テロップだけ。実際の「判断からUIになるまで」は、次の判定後に開く。

## 2. 文字列としては正しい、でも（1:25〜2:10）

**画面テロップ**：名前：株式会社北極星 / 会社名：山本花

**読み上げ**：

「例です。名前欄に『株式会社北極星』、会社名欄に『山本花』。形式チェックなら、どちらも文字列なので通ります。でも人が見ると、席が逆かもしれない。このアプリはJevに、自然、入れ替わり、判断できない、のどれかを選んでもらいます。入れ替わりの可能性が高ければ、勝手に直すのではなく、『入れ替える』ボタンを出します。押すのはユーザーです。」

**操作**：既定サンプル「名前と会社が逆」を選び、「Jevで意味をチェック」。SwapFieldsカードとボタンを表示し、その後「判断からUIになるまで」を開く。ボタンは押さずに説明してもよい。

## 3. 確率をどう使うか（2:10〜2:55）

**画面テロップ**：選択肢の確率 70%以上 → 提案 / それ未満 → 確認

**読み上げ**：

「アプリでは、選ばれた選択肢の probability が0.70以上なら具体的な提案を出し、それ未満や欠落、unclearなら確認に回します。ここで表示する90対10のような数字は説明用の架空例です。確率は正解率でも、事実確認の証明でもありません。だから選択確率が低いときに、無理に緑の成功画面にはしません。」

**操作**：実画面は使わず、90/10と55/45の説明用テロップだけを表示する。

## 4. 3つの実演（2:55〜4:15）

**画面テロップ**：判断 → 用意済みUI部品 → ユーザー確認

**読み上げ**：

「もう二つ見ます。『灯台コーヒー』のように法人格が付かない屋号も、会社名として自然と判断できます。屋号や個人事業主を即座に弾きません。判断が曖昧なら、確認に回せます。次に『いい感じにお願いします』。これは不具合なのか、相談なのか、具体的に何をすればいいのかが足りません。そこで追加で聞くUIを出します。

ここで重要なのは、Jevが自由な画面を直接生成しているわけではないことです。Jevは選択肢を判断する。アプリはあらかじめ用意した確認、カテゴリ提案、追加質問の部品を決定論的に組み立てる。入力は勝手に修正しないし、会社の実在確認もしていません。」

**操作**：順に「屋号だけですが何か？」「いい感じにお願いします」を選択して実行。形式チェックと意味チェック結果を見せる。確認カードの出現は前提にしない。追加質問欄が出たら、入力せず部品であることを見せる。

## 5. 普通のAIでもできるよね？（4:15〜5:45）

**画面テロップ**：同じ8件・32判断・各モデル1回

**読み上げ**：

「もちろん、普通のAIでもこの種のJSONは作れます。そこで比較画面では、同じ8件、32個の判断を、Jev、GPT 5.6 Luna、Gemini 3.8 Flash、Claude Haiku 4.5、Qwen 3.8 Flashに一回ずつ送ります。Jevは評価API、他はJSON生成ですが、質問と選択肢はそろえています。ここでは通信と出力完了までを測ります。」

## 6. 判断の違いを30秒だけ（5:45〜6:15）

**画面テロップ**：全員「具体性は不足」、意図は割れた

**読み上げ**：

「『お問い合わせフォームをいい感じにしてください！よろしくお願いします。』では、全モデルが『もう少し詳しく』と判断しました。一方で用途は、Jevは「用途が読み取れない」、GPTは「その他」、Geminiは「相談」、ClaudeとQwenは「その他」でした。違いは見えます。でも、ここから勝者を決めるのは早すぎます。用途に合う確認の出し方を設計する材料です。」

**操作**：比較画面の該当レコードを選び、各カードの4選択を表示。

## 7. 結び（6:15〜6:55）

**画面テロップ**：大量の小さな判断を、待たせずアプリに組み込む

**読み上げ**：

「Jevが向くのは、フォームの振り分け、追加確認、投稿分類、商品分類、軽いメールtriageのような、大量の小さな判断です。選択確率が低い判断は、人に確認してもらう。文章を考えてもらうより、小さな判断を任せたいときの選択肢です。今回は速さが目立ち、料金も低かった。うまいかどうかは、自分の用途で確かめる必要があります。今回のアプリは、判断をユーザー操作につなぐ一つの実験です。」

## 収録用事実メモ・出典

- 実測条件：2026-09-19、8件・32判断、各モデル1 call。GPT 5.6 LunaとQwen 3.8 Flashはreasoning none、Gemini 3.8 Flashはlow、JevとClaudeはprovider default。元データは [comparison-recording-evidence.json](comparison-recording-evidence.json) に保存済み。表は同ファイルから抜粋。
- Jevの選択肢 probability と confidence は別物で、どちらも正解率保証ではない。confidence は probabilities 分布の偏りを1数値に要約した統計量。フォーム側の0.70は選択肢 probability を使うUI提案の閾値。
- Jevの billed cost 0 は無料保証ではない。marketCostと請求額は別表示。
- 公式出典：[Cloudflare Jev](https://developers.cloudflare.com/ai/models/typesafe/jev/)、[Typesafe](https://typesafe.ai/)、[Typesafe Docs](https://docs.typesafe.ai/introduction)、[Confidence](https://docs.typesafe.ai/confidence)。
