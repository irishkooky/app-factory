# チューリング人狼

参加者が N 人いるとき、チャットの席は **N+1 個**ある。余った1席にはAIが座っている。
全員でお題に答え、そろったら一斉公開。最後に「どの席がAIか」を投票して当てる。

- 本番URL: https://turing-werewolf.ichigoooo.workers.dev
- 観戦モード（プロジェクタ用）: `https://turing-werewolf.ichigoooo.workers.dev/room/<code>?spectate`

## 遊び方

1. ホストが「部屋を作る」→ 4桁のルームコードが出る
2. 参加者はトップページからそのコードで入室（2人以上で開始可能、最大8人）
3. ホストが開始 → 3ラウンドのお題に全員（＋AI）が回答
4. 自由会話でお互いを探る（AIもここで割り込んでくる）
5. AI席だと思う席に投票 → 全員入れたら一斉公開

AI席が最多得票なら人間側の勝ち、それ以外はAI側の勝ち。

## セキュリティ設計 — 秘密を「返す関数を作らない」ことで守る

このアプリはログイン不要で、端末を識別するのは `localStorage` に持つ UUID だけ。
それでも成立するのは、**役職を問い合わせる経路がそもそも存在しない**ため。
なりすませたとしても、そこから引ける秘密がない。

秘密はフィールドではなく**テーブルで分離**している。

| テーブル | 公開 | 内容 |
|---|---|---|
| `rooms` / `seats` / `messages` | ✅ | 部屋の状態・席と仮名・自由会話 |
| `answers` / `votes` | ⚠️ | フェーズゲートつき（下記） |
| `roomSecrets` | ❌ | どの席がAIか |
| `seatOwners` | ❌ | どの席がどの端末のものか |

`seatOwners` を分けているのは、AI席には持ち主がいないため。`seats` に `deviceId` を持たせると
**その欄が空いている席＝AI**と一発で分かる。「持っていない」こと自体が秘密なのでテーブルごと隔離する。

### AI席が特定されうる経路と、その塞ぎ方

実装中に潰した経路。どれも「AIだけ振る舞いが違う」ことに起因する。

- **作成時刻**: AI席は `startGame` の中で作られるので必ず最後。→ 公開クエリは `{ seatId, alias, order }`
  だけを手で組み立てて返し、`_creationTime` を一切出さない。表示順は `order` で、開始時に全席をシャッフルして振り直す
- **仮名の対応**: ロビーで見えていた仮名と開始後の仮名を突き合わせると、増えた仮名＝AIと分かる。
  → 開始時に**全席（人間含む）の仮名を引き直す**ことで対応関係を切る
- **投票済みリスト**: AIは投票しないので、自分以外が全員投票済みになると未投票の席＝AIと逆算できる。
  → `getVoteStatus` は人数だけを返し、誰が投票済みかは返さない
- **提出順**: AIの提出が早いと配列の並びから推測できる。→ 回答は `seatId` 順にソートして返す
- **提出タイミング**: 即答するとバレる。→ 人間の回答が半数に達するまでAIは自分を再スケジュールして待つ
- **時間切れラウンド**: 誰も答えなかったラウンドでAIだけ回答があると、本文が出る唯一の席＝AIになる。
  → 人間の回答が2件未満のラウンドはAIの回答も伏せる（保存済みなら削除する）

回答と投票のフェーズゲートは**クエリ側**で行っている。UIで隠すのは隠したことにならない。

## 技術的な要点

- **「最後の1人か」の判定をミューテーション内で行う**。Convexのミューテーションは単一トランザクションで
  直列化されるので、2人が同時に最後の回答を送っても `reveal` は1回しか起きない。ロックも再試行も要らない
- **時間切れ処理はすべて冪等**。`forceAdvance` / `forceEndDiscussion` / `forceEndVoting` は
  フェーズとラウンドを確認し、条件に合わなければ黙って return する（ホストが手動で進めた直後に
  タイマーが発火しても二重遷移しない）
- **AI生成が失敗してもゲームを止めない**。無言はAI席の即バレなので、お題ごとに用意した
  フォールバック文を必ず保存する

## AIの生成経路

```
Convex action → 自Workerの /api/generate（共有シークレットで保護）→ Cloudflare Workers AI
```

`env.AI` バインディング経由で `@cf/meta/llama-3.3-70b-instruct-fp8-fast` を呼ぶ。
Convex側からWorkersのバインディングは直接触れないため、認証つきの薄いエンドポイントを挟んでいる。

プロンプトには現在のお題・過去の全回答（仮名つき）・他の参加者の平均文字数を渡し、
文体を寄せさせる。禁止事項（両論併記、一般論、相槌の型、丁寧すぎる敬語、40字超、
3つ以上の列挙、絵文字、「AIとして」で始める、自分の仮名を先頭に付ける）を明示している。

出力は後処理で話者名プレフィックスを剥がし、40字に収める。ただし
**短い回答は切り詰めない**（「カレー」「ラーメン」はこのゲームで最も人間らしい回答なので、
下限文字数で弾くとかえって定型文に落ちてバレる）。

## 開発

```bash
vp install
vp run build                        # vite build + tsc --noEmit

# デプロイ
npx convex deploy --cmd 'vp run build' --cmd-url-env-var-name VITE_CONVEX_URL
npx wrangler deploy
```

`vp dev` でローカル起動する場合、Vite が `.env.local` を自動で読まないことがある。
その場合は `export $(grep VITE_CONVEX_URL .env.local)` してから起動する
（読めていないとブラウザがConvexに接続できず、SSR済みの部分しか表示されない）。

### 環境変数

| 変数 | 置き場所 | 用途 |
|---|---|---|
| `VITE_CONVEX_URL` | `.env.local`（ビルド時に埋め込み） | フロントの接続先 |
| `CONVEX_DEPLOY_KEY` | `.env.local` | `convex deploy` の非対話認証 |
| `AI_ROUTE_SECRET` | Worker secret ＋ Convex env | `/api/generate` の共有シークレット |
| `AI_ENDPOINT` | Convex env | Convexから呼ぶ生成エンドポイントのURL |
